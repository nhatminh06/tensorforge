# Phase 2 showcase direction

Build the later GitHub Pages showcase from the canonical evidence contract,
after a real bundle has been captured and reviewed. The visual language should
feel like a hardware performance analysis report and lab instrument, not a
generic MLOps dashboard or AI startup landing page.

Prioritize predicted-versus-measured latency, empirical calibration ceilings,
primary-versus-contrast error, the measured regression verdict, telemetry
context, and the final impact decision. Keep analytical prediction, physical
measurement, diagnostic telemetry, and policy decisions visually distinct.
Unsupported metrics must remain unavailable rather than appearing as zero.

The exact recommendation is a static, evidence-driven report with accessible
HTML/SVG charts generated from `docs/evidence/canonical/manifest.json` and its
linked artifacts. Do not add a live backend, rerun benchmarks in the browser,
or imply cycle accuracy, silicon validation, measured bottlenecks, production
capacity planning, or model-quality assessment.
